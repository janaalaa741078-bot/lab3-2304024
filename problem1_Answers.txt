Q1.1: Insert a row in the DEPARTMENT table that references a row in the EMPLOYEE table. Then try to delete the referenced row. What will happen?
==================================================
SQL Used:
DELETE FROM EMPLOYEE WHERE ssn = '111222333';

Output / Error Message:
Error Code: 1451. Cannot delete or update a parent row: a foreign key constraint fails (`company`.`department`, CONSTRAINT `department_ibfk_1` FOREIGN KEY (`mgr_ssn`) REFERENCES `employee` (`ssn`))

Explanation:
MySQL rejects the delete operation because the employee is currently referenced as a manager (`mgr_ssn`) in the DEPARTMENT table, enforcing referential integrity.

Q1.2: Insert a row in the PROJECT table that references a row in the DEPARTMENT table that doesn't exist yet. What will happen?
==================================================
SQL Used:
INSERT INTO PROJECT (Pnumber, Pname, Plocation, Dno) VALUES (40, 'Test Project', 'Cairo', 99);

Output / Error Message:
Error Code: 1452. Cannot add or update a child row: a foreign key constraint fails (`company`.`project`, CONSTRAINT `project_ibfk_1` FOREIGN KEY (`Dno`) REFERENCES `department` (`Dnumber`))

Explanation:
MySQL rejects the insert operation because department number 99 does not exist in the referenced `DEPARTMENT` table (`Dnumber` primary key column).

Q1.3: If mgr_ssn and Dno are both NOT NULL, how will you insert the first row in EMPLOYEE or DEPARTMENT?
==================================================
SQL Used:
SET FOREIGN_KEY_CHECKS = 0;

INSERT INTO EMPLOYEE (ssn, fname, lname, bdate, address, gender, salary, Dno) 
VALUES ('111222333', 'Alice', 'Smith', '1985-03-12', 'Cairo', 'F', 75000.00, 1);

INSERT INTO DEPARTMENT (Dnumber, Dname, mgr_ssn, mgr_start_date) 
VALUES (1, 'Management', '111222333', '2020-01-01');

SET FOREIGN_KEY_CHECKS = 1;

Explanation:
When two tables have mandatory (NOT NULL) foreign keys pointing to each other, a strict insertion order fails due to the circular dependency. Temporarily setting foreign key checks to 0 (`SET FOREIGN_KEY_CHECKS = 0;`) allows you to bootstrap the first records, and resetting it to 1 re-enables full referential integrity protection.
